Product Decisions

Single seller, no login — Keeps build focused on core loop. Auth is deferred.
Simulated channels — No external API dependencies for POC. Real integrations slot in at the same data entry point.
Rule-based prioritization — Deterministic, explainable, testable. ML is deferred until real data exists.
No in-app messaging — Contact customer links out. Real-time chat is explicitly out of scope.
Linear status progression — No cancel, return, or refund paths in POC. Forward-only keeps state machine simple.
Session-only persistence — State held in memory; may reset on refresh. Acceptable for demo.
Nigerian/African business context — Seed data uses realistic names and products to ground the demo in a real use case.

What We're Building

Dashboard with four summary stat cards
Priority order list, sorted and color-coded, with plain-English reason on every row
Order detail view with all six required elements always visible
Status workflow: New → Accepted → Processing → Ready → Shipped → Completed
Primary action button that advances one step and updates immediately
Prioritization engine with 8-rule table, recalculating on every status change
Simulated order seed data (7 orders, both channels, varied statuses and ages)
"Simulate New Order" trigger for the demo
Contact customer: tel: / mailto: / wa.me/ links
Priority reason always visible on both list row and detail view

Deferred From the POC

Real WhatsApp Business API▼

The channel data structure is designed so this slots in. The API integration itself requires an approved WhatsApp Business account and is out of scope for the POC.

Real E-Commerce Platform Integration▼

Shopify, WooCommerce, or similar. Simulated for now at the same data entry point.

Persistent Data Storage▼

Orders reset on refresh. A real database (localStorage or backend) is a spec and build decision deferred past the demo.

Authentication & Multi-Seller Accounts▼

No login, no user management. Single seller for the demo.

Configurable Priority Rules, Push Notifications, Analytics▼

All deferred. Built-in defaults serve the demo. No settings UI, no alert system, no charts.

Non-Goals

🚫 Not a payment processor. Payment status is a data field only.
🚫 Not a mobile app. Web browser only. Responsive layout is fine.
🚫 Not an inventory system. Stock flags may appear; no stock levels or SKU management.
🚫 Not a CRM. Customer details are order-scoped. No history or contact database.
🚫 Not a reporting tool. No analytics, charts, or performance dashboard.
